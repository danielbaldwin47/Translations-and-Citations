# Chrome Web Store checklist for the public release (issue 57)

**One item fails review today, and six need a change before submission.** The fail is the FUMS remote-script injection (`src/content/content.js:549`, `:642-658`). The changes needed are: drop the bible-api.com host permission, write and link a privacy policy, put a Limited Use statement in it, add an in-product data disclosure that users accept, fill in the dashboard privacy fields, and make the screenshots and the 440x280 promo tile. The owner must also settle the extension name, which uses the Church's "Gospel Library" mark. Single purpose, content-script matches, package size (58.2 MB against a 2 GB limit) and a twice-yearly data refresh all pass. A `scriptures.byu.edu` host permission does not change the review tier. If it arrives in an update instead of the first version, every existing install is disabled until the user accepts it. The registration fee is $5 on Chrome's own register-page screenshot and in its 2010 announcement. The Developer Agreement leaves the current amount to Google's discretion, so it stays Unknown until the payment screen shows it.

Checked **October 5, 2026** against repository commit `9f10ef0` (`main`). Only unauthenticated public GET requests were made: no dashboard, no account, no payment. Quotes come from developer.chrome.com pages fetched that day. Each page's "Last updated" stamp is listed under Sources.

The labels mean:
- **V** (Verified): stated on a cited Chrome page, or measured in this repository.
- **I** (Inferred): a consequence or recommendation drawn from verified facts.
- **U** (Unknown): no primary source settles it.

The spec facts in issue #52 are inputs, not decisions this checklist makes. These include replacing FUMS with packaged HTTP reporting, dropping bible-api.com for a bundled WEB, and moving the BYU-derived data out of `main`.

## Unknowns

- **Current registration fee.** It shows only on the dashboard payment step (item 17).
