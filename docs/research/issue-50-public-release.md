# Issue 50: a public release and translations without user keys

The simplest first-release candidate is an independent, references-only citation index with external reading links and a bundled World English Bible. Older talks can be linked without guessing: every sampled BYU talk ID resolves, and all 371 Teachings of the Prophet Joseph Smith pages have anchors. Two corpora have no open source: pre-1971 conference reports (Church-copyrighted scans) and modern conference references (the Church site bars automated access). NIV can follow through an application express license; ESV needs a separate eligibility decision; ordinary NRSV has no published new-license route. Five questions need an account or a written answer from a provider (see "Open-item register"). None of these findings clears the current extension for publication.

Checked **October 5, 2026** (earlier pass: October 3), against repository commit `116dc6b4ed6a4f98a6fd2bce5c89ff41897be39f`. Scope includes [issue 50](https://github.com/danielbaldwin47/Translations-and-Citations/issues/50) and its [translation addendum](https://github.com/danielbaldwin47/Translations-and-Citations/issues/50#issuecomment-5972019512). This is a research decision record, not a licensing opinion, release specification, or provider application.

**Verified** means inspected repository code/data, a measurement run on October 5, or an identified primary source. **Inferred** means a proposed consequence or design. **Unknown** means evidence needed before promising that behavior. Repository citations are `path:line` at the commit above (`git show 116dc6b:<path>`); the working tree has one uncommitted line in `src/citations/talk-source.js`, which no claim here depends on. The pass used unauthenticated public GET/HEAD requests only: no credentials, account catalogs, paid API calls, deployment, publication, or outreach.

## Independent acquisition: use the permitted material first

The Copyright Office distinguishes database facts from protectable selection/coordination/arrangement: protection is unavailable for "individual plain facts" and for "the selection and ordering of data in a database where the collection and arrangement of the material is a mechanical task only". Independently identifying explicit references is a credible direction; copying BYU's selection, allusion judgments, snippets, or annotations and changing the schema does not establish independence. This is an inference from [database guidance](https://www.copyright.gov/register/tx-databases.html), not clearance of any particular dataset.

## ESV, NIV and the exact NRSV editions

### ESV through Crossway

Verified published conditions: free noncommercial API use extends to apps/digital media when all general conditions hold. The service is "available for use only by individuals and non-commercial organizations that use the service in ways consistent with the historic Christian understanding of doctrine and the Bible," and the conditions state it "is intended primarily for personal, church, and Christian ministry organization use." Gospel Library context alone establishes neither approval nor rejection. [Crossway conditions](https://api.esv.org/).

The limits are 5,000 queries/day, no more than 1,000 an hour and 60 a minute; excess is throttled. A request may return up to 500 verses or half a book, whichever is less, "excepting single-chapter and double-chapter books". The display rule ("You may not display more than 500 verses or one-half of any book (whichever is less) on any page") states no such exception, so a one- or two-chapter book shown whole is ambiguous; ask Crossway. Local storage allows at most 500 verses or one-half of any book. The cache rule reads "You can cache up to 500 verses. We encourage you to periodically clear out your cache"; no numeric interval is published. Redistribution has separate 500-verse and 50% conditions. [Crossway conditions](https://api.esv.org/).

Preserve returned copyright notices, mark passages ESV, link www.esv.org on each displaying page, and reproduce an official complete notice on a copyright page. Words may not be changed; headings, footnotes, cross-references and verse numbers may be omitted. "You may not sell, share, or publish your access key." Above-limit formal licensing is for organizations: "Our policy is to license to organizations, not to individuals or solo developers." Authentication is `Authorization: Token …`; the docs do not say whether a key may sit in browser code, so keep the application credential on the backend. [API documentation](https://api.esv.org/docs/).

API.Bible says ESV is unavailable there: "the only official way to access it is through Crossway's own ESV API." A paid API.Bible upgrade cannot supply it. [Express license FAQ](https://care.api.bible/article/405-express-licensing-faqs), updated October 1, 2026. Unknown (U2): whether this extension and developer qualify, and how Crossway applies the 500-verse storage ceiling across a shared multi-user backend. Start an eligible ESV design without a shared text cache until that scope is settled.

### NIV through an express license

Biblica explicitly offers royalty-free express licensing through API.Bible or YouVersion for apps that are truly noncommercial (no sales, subscriptions, advertising or monetization) and have no AI/ML features or functionality; platform fees can still apply; any use with AI, machine learning, large language models or chatbots needs a Biblica license expressly permitting it. Source: excerpt of [Biblica permissions](https://www.biblica.com/permissions/) from a search result on October 5. The page itself returned HTTP 403 to automated fetch both times, so its wording was not re-read in full; the October 3 reading of the registered-legal-entity requirement for direct full-Bible licensing is carried forward unverified this pass. Biblica's [permission request form](https://www.biblica.com/permission-request-form/) asks whether the requester applies "On behalf of a legal entity" or "As an individual" and for organization type (for-profit or non-profit).

The repository has no AI feature or AI host: `manifest.json:7-10` lists only `api.scripture.api.bible` and `bible-api.com`. An application built with coding assistance is different from an application offering AI features; the app-level no-AI condition still matters if product scope changes. Biblica's general 500-verse allowance is not a full chapter browser license.

For API.Bible, select NIV for the intended application and retain its actual express agreement/version metadata. Do not infer entitlement from the existing personal key. The attribution rule: "a notice on your app's 'About' or 'Settings' page, plus a brief citation (e.g., 'NASB') immediately following any quoted text". [API.Bible express licensing FAQ](https://care.api.bible/article/405-express-licensing-faqs). The terms' Appendix B lists the NIV notice ("Copyright © 1973, 1978, 1984, 2011 by Biblica, Inc.") among examples. [API.Bible terms](https://api.bible/terms-and-conditions). Unknown (B2): exact NIV edition, territory, attribution wording and application entitlement, which need an authenticated account.

### Ordinary NRSV, NRSV-CE and NRSVue

Friendship Press says: "Except for the NRSV-CE, the NRSV is no longer available for new licenses or permission agreements." NRSVue is the updated translation, not a silent equivalent to the requested NRSV. "Mobile apps, downloadable book or Bible, and software are examples of digital usages that will require a special permission or license"; the gratis 500-verse allowance "does not apply to Phone Applications, or other New Media Platforms (web sites, apps, etc.)". [Rights-holder guidelines](https://www.friendshippress.org/pages/nrsvue-quick-faq). The guidelines mention no API platform or sublicensing arrangement.

Requests go to Petradi Rights Management, `NCCrights@petradirights.com`, and the guidelines ask for the translation and verse scope, intended use, product name, audience, territory, first-use date, quantities, and, for no-charge distribution, "an explanation". ## A small backend can remove key setup

Proposed request flow, conditional on application licenses:

1. The installed extension sends an allowed edition and bounded chapter/passage request to its own backend. It needs no user provider account or key.
2. The backend validates passage bounds, allowed translations, request size and permitted geography before using a provider credential held in a [Worker secret](https://developers.cloudflare.com/workers/configuration/secrets/) ("secret values are not visible within Wrangler or Cloudflare dashboard after you define them"). It returns text plus version/rights metadata, never the credential.
3. The extension renders sanitized data with attribution and reports actual displays using packaged reporting logic. Licensed device/session identifiers can be created internally without a setup screen.
4. A provider-specific quota controller enforces account limits, cache rules, suspension/removal and a spending ceiling. On exhaustion, show an explicit unavailable state or an openly licensed alternative selected by the reader.

This is an inferred design, not a deployed service. Keep one outward passage contract with separate ESV/API.Bible/YouVersion adapters; do not force one provider's cache/reporting rules onto another. The backend does not need to change the extension's no-build/IIFE/classic-worker rules. A new backend origin needs an explicit manifest host permission (`manifest.json:7-10`).

Public extension code cannot keep an embedded client secret. Origin/CORS checks do not authenticate arbitrary callers. Constrain the relay to this application's allowed passages, add abuse controls and per-install/request limits, and enforce a global provider budget before an upstream request. Anonymous installation tokens add friction to abuse but do not prove a genuine installation; stronger attestation/authentication needs a separate product choice. Avoid exposing arbitrary URLs or provider endpoints. These are engineering inferences from the public-client/backend boundary.

Cloudflare's rate-limit binding "is permissive, eventually consistent, and intentionally designed to not be used as an accurate accounting system", with a separate limit per Cloudflare location and periods of 10 or 60 seconds, so it cannot enforce an exact worldwide monthly provider quota. [Rate-limit behavior](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/). Use authoritative shared accounting for a hard upstream spending limit. Keys, passage text and persistent identifiers should be excluded from routine logs; the operator must still account for IP addresses and passages crossing its service.
